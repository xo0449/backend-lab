# 모듈 작성 규약

모듈 하나는 폴더 하나입니다. 등록 절차는 없습니다.
웹이 이 폴더를 읽어 목록을 만듭니다.

## 필수 파일

```
modules/<slug>/
├── meta.json      웹이 읽는 메타데이터
├── README.md      글
├── src/           구현
└── bench/         측정과 재현 스크립트
```

## README 구조

```markdown
# 제목

## 상황
언제 누가 무엇을 하다가 부딪히는지. 추상적인 서술 대신 장면으로.

## 확인하고 싶었던 것
이 모듈이 답하려는 질문 하나.

## 재현
문제가 실제로 일어나는 것을 보여준다. 숫자와 함께.

## 접근
무엇을 했는지. 고려했다가 버린 선택지를 함께 적는다.

## 결과
실험이면 측정 전후. 구현이면 내린 결정과 이유.

## 다시 한다면
바꿀 부분. 이 모듈이 다루지 않은 것.

---

## 직접 실행해보기
맨 아래에 부록으로 둔다. 아래 규칙 참고.
```

## 직접 실행해보기 규칙

**모든 모듈은 이 절을 가진다.** 읽은 사람이 바로 돌려볼 수 있어야
글의 주장에 힘이 생깁니다.

- 클론부터 시작하는 명령을 맨 앞에 둔다. 앞 절을 안 읽어도 되게 한다
- 케이스마다 명령을 따로 준다. 전부 돌리는 명령과 하나만 돌리는 명령을 나눈다
- 숫자를 바꿔보는 방법을 준다. 환경변수로 규모나 조건을 조정할 수 있게 한다
- **결론을 뒤집어보는 방법을 하나 넣는다.** 코드 한 줄을 지우면
  개선 전 상태로 돌아가는 식이다. 그래야 인과가 확인된다
- 상태를 직접 들여다보는 명령을 준다. SQL 한 줄, 컨테이너 명령 한 줄
- 테스트 실행 명령으로 끝낸다. Docker를 쓴다면 정리 명령까지

적어둔 명령은 반드시 직접 실행해서 되는지 확인합니다.
안 되는 명령이 하나 있으면 나머지도 의심받습니다.

## 실행 스크립트

각 모듈의 벤치를 루트 `package.json`에 `lab:<이름>`으로 등록합니다.

```bash
npm run lab:aggregation
npm run lab:cron
```

시나리오가 여럿이면 `ONLY=n`으로 하나만 돌릴 수 있게 합니다.

## meta.json 규칙

`question`은 비울 수 없습니다.
실험은 `metrics`가, 구현은 `decisions`가 있어야 합니다.
검증은 `shared/module-meta.ts`에 있고, 웹 빌드가 이를 실행합니다.
고민 항목이 비어 있으면 빌드가 실패합니다.
